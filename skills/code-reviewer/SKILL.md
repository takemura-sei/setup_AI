# code-reviewer

## 何をするものか

`project-bootstrap` スキルのテンプレートに含まれる `.claude/agents/code-reviewer.md` を、新規プロジェクト作成時に限らず独立して呼び出せるようにするSkill。対象プロジェクトの `CLAUDE.md` や `.claude/docs/` 配下のドキュメントを読み込み、TDD必須・レイヤーごとの責務・命名規則・`runtimeConfig` の罠など、そのプロジェクト固有のルールに基づいてdiffをレビューするサブエージェント定義を生成する。

一般的なバグ・簡素化観点のレビューを行う `code-review` スキルに対して、本Skillが生成するサブエージェントは「プロジェクト規約への準拠」に特化する。役割が異なるため、両者は排他ではなく併用を想定している。

## 呼び出しタイミング

- 「コードレビュー用のサブエージェントを作って」「project-bootstrapのcode-reviewerを単体で使いたい」と言われたとき
- 新規プロジェクトのセットアップ（`project-bootstrap`）とは別に、既存プロジェクトへ後から規約チェック用のレビューエージェントを追加したいとき
- `CLAUDE.md` や `.claude/docs/` 配下の規約ドキュメントが増えてきて、レビュー時の見落としが気になり始めたとき

## 事前準備: プロジェクト規約の検出

生成前に、対象プロジェクトの規約を実際に読み込んで把握する。要約や記憶に頼らず、都度ファイルを確認すること。

1. `CLAUDE.md` を読み、技術スタック・コマンド一覧・プロジェクト固有ルールを確認する
2. `.claude/docs/` 配下のドキュメント（`development.md` / `architecture.md` など、存在するもの）を確認し、以下の観点がまとまっていないか探す
   - TDD・テスト配置ルール（テストファイルの配置場所、`src/` 構造とのミラーなど）
   - レイヤーごとの責務（例: server/api → service → store → composable → component → page）
   - 命名規則
   - 環境変数・`runtimeConfig` など、プロジェクト固有の既知の罠
3. ドキュメントが存在しない、または上記観点が明文化されていない場合は、生成するサブエージェントの指摘対象を一般的なベストプラクティスに留め、「プロジェクト固有の規約ドキュメントが見つからなかった」旨をユーザーに申し送りする

## 生成対象ファイル

`.claude/agents/code-reviewer.md`

## テンプレート構成

`templates/code-reviewer.md.template` … サブエージェント定義本体（Frontmatter + システムプロンプト）。プレースホルダーは以下の通り、単純文字列置換で埋める。

- `__PROJECT_DOCS_PATHS__` … 規約が書かれているドキュメントのパス一覧（例: `CLAUDE.md`, `.claude/docs/development.md`）。サブエージェントが実行時にも一次情報として参照できるよう、パスをそのまま埋め込む
- `__PROJECT_DOCS_SUMMARY__` … 事前準備で収集した規約の要約（箇条書き）。TDD・レイヤー・命名規則・既知の罠など、検出できたものだけを列挙する。何も検出できなかった場合は「規約ドキュメントが見つからなかったため、一般的なベストプラクティスに基づいて指摘する」と明記する

## 生成手順

1. 事前準備でプロジェクト規約を検出する
2. `templates/code-reviewer.md.template` を読み、`__PROJECT_DOCS_PATHS__` / `__PROJECT_DOCS_SUMMARY__` を置換する
3. `.claude/agents/code-reviewer.md` として書き出す
4. 既に同名のファイルが存在する場合は上書きせずユーザーに確認する（破壊的操作のため）
5. 生成後、実際のPR diff（または直近のdiff）に対してサブエージェントを呼び出し、規約違反を検出できるか簡単に試す

## ユーザー確認が必要な操作

- 既存の `.claude/agents/code-reviewer.md` への上書き
- 規約ドキュメントが検出できず、指摘対象を一般的なベストプラクティスに留めるかどうかの判断

## 制約・注意点

- 本Skill自身はレビューを実行しない。あくまで「レビューを行うサブエージェント定義」を生成するだけで、生成後の実際のレビューは生成された `code-reviewer` サブエージェントを呼び出して行う
- 検出できるのはドキュメント化された規約のみ。暗黙のルール（レビューコメントの蓄積など、文書化されていない慣習）までは拾えない
- diffの取得方法（`git diff` の実行、GitHub PRのdiff取得など）は呼び出し側の環境に依存する。テンプレートのシステムプロンプトは「レビュー対象のdiffが渡される・または自身で取得できる」前提で指摘を返す設計にしている

## 使用例

```
code-reviewerでレビュー用サブエージェントを作って
```

→ 対象プロジェクトの `CLAUDE.md` ・ `.claude/docs/` を読み込み、検出した規約を反映した `.claude/agents/code-reviewer.md` が生成される。
