# env-doctor

## 何をするものか

`.env` 設定漏れに起因する不具合の切り分けを支援するSkill。

1. `.env.example`（プロジェクトによっては `.env.sample` 等）に列挙されている環境変数と、コード中で実際に参照されている環境変数（`process.env.*`、Nuxtの `runtimeConfig` / `useRuntimeConfig()` 経由の参照など）を突き合わせる
2. 次のようなズレを検出して一覧化する
   - コードで参照されているが `.env.example` に記載がない変数
   - `.env.example` に記載があるがコード中で参照されていない変数（不要になった可能性）
   - `.env.example` には存在するが、実行環境の `.env`（ローカルの場合）で値が空・未設定になっている変数
3. Supabaseを使うプロジェクトでは、接続に必要な環境変数（`SUPABASE_URL` / `SUPABASE_ANON_KEY` 等、プロジェクトの実際の変数名に合わせる）が揃っているかを確認し、Supabase MCPサーバー経由で疎通確認できる場合は簡易ヘルスチェックを行う

本Skillは検出・報告までを担当し、`.env` ファイルへの値の書き込みは行わない（値の中身は秘匿情報のため、常にユーザー自身に設定してもらう）。

## 呼び出しタイミング

- 「.envまわりを確認して」「環境変数の設定漏れがないか調べて」と言われたとき
- ローカル起動・ビルド・テストが環境変数絡みのエラー（`undefined` の参照など）で失敗し、原因切り分けをしたいとき
- 新しいメンバー・別環境向けに `.env.example` の過不足を棚卸ししたいとき

## 前提条件

- 対象プロジェクトに `.env.example`（相当のテンプレートファイル）が存在すること。存在しない場合は、その旨を伝えた上で「まず `.env.example` を作るところから始めるか」をユーザーに確認する
- Supabaseヘルスチェックを行う場合は、Supabase MCPサーバーに接続済みで対象プロジェクトを操作できること。接続がなければヘルスチェック部分はスキップし、その旨を報告する

## 実行手順

1. **テンプレートの読み込み**: `.env.example`（見つからなければ `.env.sample` 等の類似ファイルも探す）を読み込み、記載されているキー一覧を取得する
2. **コード中の参照箇所の検索**: `process.env.<KEY>` と、Nuxtプロジェクトであれば `runtimeConfig` / `useRuntimeConfig()` 経由のキー（`nuxt.config.ts` の `runtimeConfig` 定義とその参照箇所）を横断的に検索し、実際に使われている環境変数キー一覧を作る
3. **突き合わせ**: 1と2の一覧を比較し、次の3種類の差分を作る
   - コードで参照 かつ `.env.example` に記載なし（記載漏れ候補）
   - `.env.example` に記載 かつ コードで未参照（不要候補）
   - `.env.example` に記載 かつ ローカルの `.env` で値が空/未設定（設定漏れ候補。`.env` が存在しない場合はこの項目はスキップし、その旨を明記する）
4. **報告**: 差分をキー単位でユーザーに提示する。記載漏れ・設定漏れは対処の目安（`.env.example` への追記案、設定すべき値の取得元など分かる範囲で）を添える
5. **Supabaseヘルスチェック（該当プロジェクトのみ）**: Supabase関連の環境変数が揃っている場合、Supabase MCPサーバー経由で対象プロジェクトへの疎通を確認し、結果を報告する。変数が揃っていない、またはMCP未接続の場合はこの手順をスキップした旨を明記する

## ユーザー確認が必要な操作

- `.env.example` への追記・削除（本Skillは差分提示までとし、反映はユーザー確認の上で行う）

## 制約・注意点

- `.env` ファイル自体の値（秘匿情報を含む）は書き込まない。あくまで「キーが設定されているかどうか」のみを扱い、値の中身をログ・報告に含めない
- `process.env.*` の動的なキー生成（テンプレートリテラルや変数経由でのアクセスなど）は静的検索では検出できない場合がある。検出漏れの可能性がある旨をあわせて報告する
- `runtimeConfig` はNuxt固有の仕組みのため、Nuxt以外のプロジェクトでは `process.env.*` の参照のみを対象とする
- Supabaseヘルスチェックは、Supabase MCPサーバーに接続していない環境（Supabase CLIのみのローカル環境など）では実行できない

## 使用例

```
env-doctorでpokemon_apply_v2の.env設定漏れがないか調べて
```

→ `.env.example` とコード中の `process.env.*` / `runtimeConfig` 参照を突き合わせ、記載漏れ・未参照・未設定の各候補を一覧化し、Supabase接続情報が揃っていれば疎通確認まで行う。
